# Apply runner preparation (inert)

These modules are not exported by the public Action, used by any workflow, or connected to the App. They test the signed-envelope and commit-only boundaries before an opt-in trusted workflow exists. They cannot write a repository on their own.

`verifyApplyEnvelope` accepts a bounded, strictly shaped Ed25519 envelope and a pinned public key provided by trusted Action code. The parsed dispatch payload, public PR comments, and artifacts remain untrusted; signature validation is only the first gate. The caller must independently verify the installed repository, open same-repository PR, current maintainer permission, current bot-owned canonical comment and selected tick state, exact scan provenance and eligible finding evidence at the pinned head. It must also reject nonces/delivery IDs already consumed and handle crashes and retries by reading the branch before any new write. This module does not supply those checks or a replay store.

`commitVerifiedBatch` is a narrow dependency-injected commit boundary. The future implementation of `CommitOnlyPort.revalidate` must consume hash-bound, runner-verified bytes and re-read current GitHub state with read-only calls. Its `createCommit` must create blobs/tree/commit without checking out the PR or invoking a package manager. Its `updateRefNonForce` must update the PR head with `force: false` on the exact branch after a commit whose parent is the old head; a moved head makes the update non-fast-forward and refuses rather than overwriting. Use only a short-lived, single-repository dedicated App installation token, not workflow `GITHUB_TOKEN`. A token, private key, package-manager executable or PR code must never enter the same process as this commit-only job. A race between the last head read and ref update is rejected by the non-fast-forward API update. Ambiguous network errors after ref update need branch/commit readback before any retry.

The signature envelope currently binds metadata but not the verified file hashes. Before enabling the workflow, bind a deterministic digest of changed-path/content-hash tuples to the signed envelope or equivalent authenticated provenance and verify it in the commit-only job. These stubs deliberately stop short of production wiring and do not establish the slice-2 evidence, M3 stability, ADR-0004 boundary, token-triggered CI, or security acceptance gates. Do not enable a workflow from this directory as-is.
