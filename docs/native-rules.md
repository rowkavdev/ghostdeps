# Adding a JS native-replacement rule

The seed catalog in `packages/core/src/native-rules/rules.ts` lists versioned candidates. The production path can produce a `potentially-unnecessary` finding only after the JS/TS adapter's citations pass core's matched-API, incompatible-pattern, semantic-flow and deployment checks, a verified scanner snapshot, the envelope seal and the policy gate. Missing or uncertain evidence blocks; the CLI JSON `nativeEvaluations` field and human `Native evaluation` section name blocked and no-verdict outcomes. This is a review suggestion, never an automatic code change.

1. Add a versioned data object under `packages/core/src/native-rules/`, with a stable ID, exact package and covered APIs, a conservative runtime floor for every supported target, incompatible uses, semantic differences, confidence criteria and primary references. Add it to the catalog. Increment the ID version when coverage or semantics change.
2. Keep the rule narrow. For example, `uuid` v4 string generation is not UUID parsing or custom RNG; `lodash.clonedeep` on plain cloneable data is not cloning functions, prototypes or descriptors. A browser-only target cannot inherit a Node floor.
3. Add real-repository positive and adversarial fixtures for each new rule: incomplete references, unknown or below-floor targets, unresolved uses or options, unsupported APIs, observed or unchecked incompatibilities and missing semantic checks must block. The rule must author compatible pattern syntax kinds, and core must validate every claimed flow.
4. Never run code from the scanned repository to decide eligibility. Never infer the deployment floor from the CI matrix alone. A rule definition alone produces no finding; the full source-backed pipeline must seal it.

Sources for the initial rules: [Node crypto](https://nodejs.org/api/crypto.html), [Node globals](https://nodejs.org/api/globals.html), [MDN structured clone](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Structured_clone_algorithm), [Axios docs](https://axios-http.com/docs/handling_errors), [uuid](https://github.com/uuidjs/uuid#readme), and [Lodash](https://lodash.com/docs/4.17.15#cloneDeep).
