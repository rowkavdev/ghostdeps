# Configuration

Choose the channel first. The CLI and Action run locally without a registry metadata provider. The GitHub App can opt in to public npm install-size lookups. There is no repository config file or per-installation settings page. Flags and Action inputs are per run; App environment values apply to the running service. See [CLI](cli.md), [GitHub Action](github-action.md), and [self-hosting](deployment.md) for usage and setup.

## CLI scan

| Name                              | Default          | Effect                                                                                                                                                                | When to touch it                                              |
| --------------------------------- | ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| `ghostdeps scan [path]`           | `.`              | Selects the directory to scan.                                                                                                                                        | When scanning a directory other than the current one.         |
| `--json`                          | Off              | Prints the complete schema-versioned result; not filtered by `--severity`.                                                                                            | When another tool consumes the result.                        |
| `--fail-on <severity>`            | Unset (advisory) | Exits 1 if any verdict finding reaches `critical`, `high`, `medium`, `low`, or `info`. Evaluates all verdict findings, even those hidden by the human display filter. | When deliberately making findings a CI gate.                  |
| `--severity <severity>`           | Unset (show all) | Filters human display only; cannot be combined with `--json`.                                                                                                         | When you only want to read findings at or above a threshold.  |
| `--disable-rule <id>`             | None             | Disables one recommendation rule; repeatable.                                                                                                                         | When a rule is not appropriate for this run.                  |
| `--downgrade <rule>=<confidence>` | None             | Caps a rule's confidence at `high`, `medium`, or `low`; repeatable and never raises it.                                                                               | When a rule needs a more cautious verdict.                    |
| `--allowlist <ecosystem>:<name>`  | None             | Marks expected tooling; a trailing `*` matches a name prefix. Repeatable.                                                                                             | When a known tool is expected despite weak source references. |

`--fail-on` and the policy flags apply only to `scan`. Unknown rule IDs or ecosystems are usage errors, not silently ignored. Awareness notes and factual health observations never trigger `--fail-on`, even at `info`. A successful scan exits 0 unless its `--fail-on` threshold is reached (exit 1); usage and scan errors exit 2, and unimplemented commands exit 3. No `--fail-on` means findings do not fail a successful scan. The CLI is offline and does not fetch registry metadata. See [CLI flags and exit codes](cli.md#flags).

## GitHub Action

Set these under `with:` for `rowkavdev/ghostdeps/packages/action@v1`. The Action runs the CLI in your runner and does not enable the App's npm metadata provider.

| Input          | Default               | Effect                                                                                                                                                                   | When to touch it                                 |
| -------------- | --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------ |
| `path`         | `.`                   | Directory scanned relative to the workspace.                                                                                                                             | When the checkout or project lives elsewhere.    |
| `fail-on`      | Empty (advisory)      | Passes the severity threshold to the CLI and fails the **step** on a finding at or above it. The posted GhostDeps check remains `success` or `neutral`, never `failure`. | When the workflow should gate on findings.       |
| `disable-rule` | Empty                 | Comma-separated rule IDs disabled for the run.                                                                                                                           | When specific recommendation rules do not apply. |
| `allowlist`    | Empty                 | Comma-separated `ecosystem:name` tooling entries.                                                                                                                        | For expected tooling not referenced in code.     |
| `check-name`   | `ghostdeps`           | Name of the check run.                                                                                                                                                   | To distinguish this check from another check.    |
| `node-version` | `22`                  | Node version used for analysis; requires Node 22 or newer.                                                                                                               | When your runner needs a newer supported Node.   |
| `github-token` | `${{ github.token }}` | Token for creating the check run; workflow needs `checks: write` (and `contents: read` for checkout, `pull-requests: read` for PR annotations).                          | When a different authorized token is needed.     |

| Output       | Default                   | Effect                                                                                                                                                                                      | When to touch it                                                                                             |
| ------------ | ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `conclusion` | No output until rendering | Rendered check conclusion (`success` or `neutral`). On a fork PR it is still set, but the read-only default token cannot post a check; do not treat this output as proof of a posted check. | Read in later workflow steps for the advisory result; check for a posted check separately when that matters. |
| `scan-exit`  | No output until scan      | CLI exit code (`0` for successful analysis, `1` for a `fail-on` threshold, `2` for a usage or scan error).                                                                                  | Read when distinguishing findings from a scan that did not complete.                                         |

On a fork PR, the Action falls back to up to 10 workflow notices plus a job summary; it cannot create a check run with a read-only `GITHUB_TOKEN`. A CLI scan error does not become a `fail-on` failure: inspect the job warning and result rather than treating it as a clean scan. See [Action behavior and limits](github-action.md).

## GitHub App environment

Store secrets in the host's secret manager, not in Git or logs. These are process-wide values, not per-repository switches.

| Name                          | Default         | Effect                                                                                                                                       | When to touch it                                                        |
| ----------------------------- | --------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| `APP_ID`                      | Required        | Positive numeric GitHub App ID. An invalid or missing value prevents check-run writes.                                                       | When registering the App.                                               |
| `PRIVATE_KEY`                 | Required        | App private key for authentication.                                                                                                          | On registration or key rotation.                                        |
| `WEBHOOK_SECRET`              | Required        | Verifies incoming webhook signatures.                                                                                                        | On registration or secret rotation.                                     |
| `NODE_ENV`                    | Runtime default | Set `production` for production logging and to disable Probot setup mode.                                                                    | On deployment.                                                          |
| `PORT`                        | `3000`          | HTTP listener port.                                                                                                                          | When the host/proxy uses another port.                                  |
| `HOST`                        | Loopback        | HTTP listener address; expose `0.0.0.0` only behind a trusted proxy/container network.                                                       | When your deployment needs network binding.                             |
| `LOG_LEVEL`                   | `info`          | Probot log level.                                                                                                                            | For temporary diagnosis without logging secrets or repository contents. |
| `GHOSTDEPS_SOURCE_PR_TRIGGER` | On              | `false` or `0` disables analysis of source-only PR changes.                                                                                  | When intentionally limiting PR triggers to manifest/lockfile changes.   |
| `GHOSTDEPS_RECOMMENDATIONS`   | On              | `false` or `0` suppresses verdicts and reports facts only.                                                                                   | When using the App for facts without recommendation verdicts.           |
| `GHOSTDEPS_FOOTPRINT`         | **Off**         | Only `true` or `1` enables the App's public npm install-footprint provider. Unset, `false`, `0`, and other values leave it off.              | When opting in to public npm metadata egress and advisory size facts.   |
| `GHOSTDEPS_RELEASE_ID`        | Absent          | Valid release tag appears as `/healthz` `version`; 1-64 ASCII letters/digits/`.`/`_`/`-`, starting alphanumeric. Invalid values are omitted. | When labeling a deployed build for liveness checks.                     |

The App's check conclusions are advisory, not a `fail-on` gate. `GHOSTDEPS_FOOTPRINT` does not enable private-registry queries, Python/Rust/Go metadata, or metadata lookups in the CLI/Action. The optional provider supplies footprint sizes; `packageFacts` is an additive contract for source-backed health observations on exact locked direct dependencies. Their presence does not change verdicts, check conclusions or the CLI gate. A missing origin or metadata response yields no fact, not a zero or a warning. See [App behavior](github-app.md) and [security model](security-model.md).

## Library and provider limits

These are code-level options for integrators, **not environment variables or Action inputs**. The shipped CLI and App do not expose a user setting for them. Keep the defaults unless the host's capacity or a measured partial-run problem calls for a reviewed change.

| Option or limit                                                                | Default                                                                                            | Effect                                                                                                                                 | When to touch it                                                       |
| ------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| `GhostDepsAppOptions.sourcePrTrigger`, `.recommendations`, `.footprint`        | On, on, off                                                                                        | Programmatic counterparts to the three App flags above; options override environment values.                                           | When embedding the App rather than using its normal environment setup. |
| `GhostDepsAppOptions.appId`, `.releaseId`, `.busyLimiter`, `.queue`, `.worker` | App ID and release ID from env; built-in limiter/queue/worker                                      | App identity, health label and internal job scheduling.                                                                                | Only for a custom App host or test harness.                            |
| `AnalysisWorkerOptions.metadata`, `.scan`, `.resultCache`                      | No provider unless App footprint is on; core scan defaults; 16 MiB/4 entries per repo result cache | Caller-supplied metadata service, checkout scan limits, and same-SHA result caching (`false` disables cache).                          | For a custom worker or measured capacity limit.                        |
| `NpmMetadataOptions.fetchBudget`                                               | 300 requests initially, automatically grows with public versions to at most 1,000                  | Shared per-analysis request cap across size and health calls; an explicit value is fixed and does not grow.                            | To set a hard egress cap for a custom provider.                        |
| `NpmMetadataOptions.requestTimeoutMs`, `.runTimeoutMs`                         | 3,000 ms, 8,000 ms                                                                                 | Per-request timeout and provider-run deadline. Core separately stops waiting for an install-size answer at 10,000 ms per ecosystem.    | When a custom host needs a shorter deadline.                           |
| `NpmMetadataOptions.concurrency`, `.maxResponseBytes`                          | 8 workers (up to 16 on large sets), 1 MiB streamed body                                            | Bounds parallel GETs and memory read from each npm response.                                                                           | After measuring throughput and memory, without removing caps.          |
| `NpmMetadataOptions.maxVersions`, `.maxAnswers`                                | 50,000 per version/fact cache, 256 whole answers                                                   | Process-local LRU entry limits.                                                                                                        | When tuning a long-lived worker's memory.                              |
| `NpmMetadataOptions.versionTtlMs`, `.answerTtlMs`                              | 24 hours, 1 hour                                                                                   | Expiry for positive/known-missing version facts and complete dependency-set answers. Transient and truncated responses are not cached. | When fresher registry data justifies more requests.                    |
| `AnalyseOptions.adapterTimeoutMs`, `.usageConcurrency`                         | 60,000 ms per stage, 8 usage calls per adapter                                                     | Limits an adapter's stage time and usage concurrency.                                                                                  | For a custom engine host after profiling.                              |
| `IsolatedAnalyseOptions.adapterHeapMb`, `.maxParallelAdapters`                 | 512 MiB old-generation heap per worker, 4 parallel adapters                                        | Worker-thread memory/concurrency bounds, not OS isolation or a whole-process cap.                                                      | When provisioning a custom host with measured peak memory.             |

The provider accepts only exact, publicly resolved npm packages: core's `PUBLIC_NPM_REGISTRY_ORIGINS` is `https://registry.npmjs.org` and `https://registry.yarnpkg.com`. It checks origins as complete values, not subdomains or suffixes; all requests go to `https://registry.npmjs.org` as unauthenticated read-only GETs with redirects refused. Do not change the allowlist through repo content or copy it into another package. The per-ecosystem registry registers only npm in v1; adding a fetcher or destination needs an explicit per-ecosystem allowlist and security review. Cache keys and egress bounds are recorded in [the security model](security-model.md#registry-metadata-service-60). Repository contents cannot select a fetcher or a network destination; lockfile origin only determines whether an already configured public npm fetcher may be used.
