Local core suite result at writing: **487 tests passed, zero failed**. `pnpm exec eslint packages/core/src/engine/fix-evidence.test.ts` and Prettier check passed. The new suite contains five cases, including two stale-source cases. Baseline `fix-preview.test.ts` already covers npm v2/v3, malformed roots, transitive consumers, incomplete scans/graphs, unknown metadata, hardlink aliases, and malformed UTF-8. This write-up does not treat the existing test count or a closed issue as proof of the remaining gates.

## Required to turn this into a release gate

- Core: replace synthetic-only proof with real JS/TS adapter fixtures for script/bin/config/dynamic references, explicit rule-specific `FixEligibilityEvidence`, user exclusions and scope digest, unique project/declaration identity, and proof that an overlay's disappearance is not from lost coverage. Test both npm v2 and v3 under a pinned runtime and unsupported formats. Assert exact before/after bytes and no writes on every refusal.
- App: simulate accepted versus declined permission reapproval; declined must leave scan-only Checks functional with no checkbox or dispatch. Independently fetch live PR, current head, maintained bot-owned comment, editor permission, scan provenance and selected ticks; stale-head and revoked-permission fixtures must dispatch zero times. Test body tampering, replay, reordered deliveries and duplicate comments.
- Runner: a trusted workflow must verify the envelope and current state independently, bind signed hashes to the exact bytes crossing jobs, reject replay, confirm npm configuration and lockfile regeneration without secrets or scripts, and use a dedicated App token for a non-force compare-and-swap. Test branch movement before and after commit creation, ambiguous post-write crash readback, and a live repository showing new-head CI and App synchronize scan. None of that exists in these fixtures.
- Governance: separately record M3 stability and the ADR-0004 runner execution/security boundary review. A repository document's statement about any earlier approval is not itself owner evidence.

Until these gates are met, the supported output is a read-only preview with explicit limits. The scaffold in draft PR #405 must remain inert. This inventory makes the pass/fail boundary inspectable; it does not claim slice 2 as a whole has passed.
